# 全 pipeline 火山图统一标签上限

原实现只限制上调前10个，下调全部标注，导致下调基因多的病例拥挤。

新实现集中在 run_casestudy.R 的 select_volcano_labels()，所有疾病和细胞类型通过同一 run_plots() 调用：

- 只标红/蓝点；沿用 FDR<0.05、|logFC|>=1 的上色规则。
- 默认上调10个、下调5个，按FDR升序选择，并列按基因名排序。
- 一侧不足时由另一侧补足，合计最多15个；合格基因不足15个则不补灰点。
- 独立火山图、ABCD中的A面板和标注基因CSV使用同一份 lab_df。
- DE数值、所有点、上下调总数、富集输入和B/C/D选择规则不因标签上限改变。

原版标签改动在 codex/volcano-label-limit 分支；donor缺失版本只应用同一标签补丁，不将取样策略合并进原 revision。历史代码summary里“下调全部标注”描述的是 c9bb6cc 时的历史行为，本说明和当前运行指南覆盖当前标签规则。

审核图与日志单独保存于主项目 webapp/sessions/volcano_labels15_review_20260923/。使用已有分析状态，仅运行绘图阶段；原session未覆盖，未重算DE/富集。PDAC CAF的原100基因仍有来源/全零问题，审核图继续标为诊断预览，不因标签变少而成为有效生物学验证；替代100基因的C/D实验也不自动替换正式pipeline。
